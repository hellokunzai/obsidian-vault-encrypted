而折叠箭头内的 `<svg>/<path>` 是 **SVGElement（非 HTMLElement）**——点箭头时首行直接 return null，

修复：首行放宽为 `instanceof Element`（SVGElement 同样有 `closest()`）。

经验：**DOM 事件 target 可能是 SVGElement；凡是拿 evt.target 做 instanceof 守卫再 closest() 的，
守卫要用 Element 而非 HTMLElement。**

## 密码一致性修复：哈希校验 + 首次弹窗（用户选「哈希校验+首次弹窗」方案）

- 问题：标记文件夹的密码只存内存，重启后清空；设置里只有 path/hint/recursive，无密码。重启后新建文件 → `getPassword` 返回空 → 弹窗让你输密码，且**输什么就是什么**，容易和当初标记密码不一致。
- 方案（对比过 Keychain 静默 / 展开即输密码 / 哈希校验+首次弹窗，用户选第三项）：
  - 标记时把 `sha256(路径 + "\0" + 密码)` 作为 `passwordVerifier` 存进设置（**不存明文**），用 `crypto.subtle.digest` 计算
  - 重启后首次自动加密弹窗输密码 → `FolderMarkService.verifyAndRemember(path, pw, hint)` 比对哈希：
    - 不匹配 → 返回 null + 提示「密码不正确」，文件**保持明文不加密**（杜绝不一致）
    - 匹配 → 存入内存，本次会话后续文件不再弹窗
  - 无 verifier 的旧标记（升级前建的）：首次输对密码即"锚定" verifier，之后统一校验
- 改动文件：
  - `IFeatureFolderEncryptSettings.ts`：`IMarkedFolder` 增 `passwordVerifier: string`
  - `FolderMarkService.ts`：增 `setSaveCallback` / `computeVerifier` / `getVerifier` / `setVerifier` / `verifyAndRemember`；`bind`/`addMark` 默认 `passwordVerifier: ""`
  - `MarkFolderModal.ts`：`commit` 标记时 `await FolderMarkService.setVerifier(path, password)`（内部调用 saveCallback 持久化）
  - `FeatureFolderEncrypt.ts`：`onload` 注册 `setSaveCallback(() => saveSettings())`；`pendingPrompts` Map 防并发自动加密重复弹窗；`promptForPassword` 改为走 `verifyAndRemember` 校验
  - `src/i18n/index.ts`：增 `modal.autoEncryptPassword.wrong`（en/zh），更新 `modal.markFolder.descNoPasswordStored` 说明
- 验证：`npm run build` 通过；dist main.js 含 `verifyAndRemember`/`passwordVerifier`/`computeVerifier` 及新键
- 注：用户现有「测试加密文件夹」是升级前标记的（无 verifier），升级后首次建文件会锚定——务必输入**当初那个密码**才能保持一致
