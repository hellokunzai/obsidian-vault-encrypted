### ⚠️ 上版修复其实是错的（key 错位），本版真正修好

**根因**：上一版的回退查 `getPathCacheKey(file.path)` 得到文件的父目录（`测试加密文件夹`），但 `FolderMarkService.putPassword` 调用的是 `putByPath(pwh, folderPath)`，而 `putByPath` 的 `getPathCacheKey` 在"无 marker"时把入参当**文件**再取父目录 → `测试加密文件夹` 被切成 `''` → 存到 `$root`。于是"一边存 `$root`、一边查 `测试加密文件夹`"，永远 miss，只有标记根目录这种巧合才碰巧能用，嵌套文件夹照旧弹框。

**真修复（本版）**：
- `SessionPasswordService.ts` 新增显式文件夹级 key：`getFolderCacheKey(folderPath)`（key = 文件夹路径本身，根目录归 `$root`）+ `getFolderOfFile(filePath)`（文件→其所在文件夹 key），并新增 `putByFolder / getByFolder / clearForFolder`。
- `getPathCacheKey(path)` 无 marker 时改为返回 `getFolderOfFile(path)`，与 `putByFolder` 同源。
- `getByFile` 回退、`getByPath(_Async)` 行内回退均落到文件夹 key。
- `FolderMarkService.putPassword/getPassword` 改用 `putByFolder/getByFolder`；`removeMark/removeFolder/renameFolder/clearPasswords` 同步 `clearForFolder`/`clear`，避免脏密码残留。
- `putByPath` 所有调用方均传 `markerIndex`（行内），不再用于文件夹级。

验证：`npm run build` 零错误。场景核对：嵌套文件夹 `测试加密文件夹/未命名123123.md` 整篇解密 → getByFile 回退查 `测试加密文件夹` key → 命中文件夹密码；根目录 `/` 文件 → 两边均归 `$root`；行内片段无独立密码时回退文件夹密码。

## vault-encrypt: 修复「记住密码时间」对加密文件夹不生效

Bug：设置「记住密码 X 分钟」后，整篇/行内加密文件会按时过期清空，但加密文件夹的密码永远留在内存（直到关闭 Obsidian），文件夹也不会重新上锁。

根因：`FolderMarkService` 用自己独立的 `passwords: Map` 作主存储（永不超时），`getPassword()` 先查它直接返回，从不触发 `SessionPasswordService.clearIfExpired()`；而 `SessionPasswordService.clear()` 只清自己的 cache，不清 `FolderMarkService.passwords`。

修复（src/services/SessionPasswordService.ts + src/features/feature-folder-encrypt/FolderMarkService.ts）：
- SessionPasswordService 新增 `clearCallbacks` 注册表 + `registerClearCallback()`，`clear()` 末尾依次调用回调。
- FolderMarkService 在 `bind()` 注册 `clearPasswordsForSession`（仅清自己 passwords，不回调 clear 避免递归），使 session 到期/手动清空时文件夹密码同步清空。
- `getPassword()` 开头先调 `SessionPasswordService.getByFolder(target)` 以滑动记住计时器并在过期时经回调清掉自身存储，再读自身 map。

验证：`npm run build` 通过（tsc + esbuild 零错误），修复已编入 dist/vault-encrypt-2.12.2/main.js。

## vault-encrypt: 新功能「密码过期后文件夹自动折叠」
